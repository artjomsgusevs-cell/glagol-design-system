# Проверки и приёмка

Свод без падающей команды через месяц становится украшением — это уже
проверено на мёртвых разделах v1.31. Поэтому у каждого правила, которое можно
проверить машиной, есть строка в стороже.

## Чем проверяем

| Команда | Что делает | Держит выкатку |
| --- | --- | --- |
| `npm run check` | гоняет всё ниже и показывает долг одной сводкой | — |
| `tsc --noEmit` | типы | да |
| `ui-guard.mjs` | список конкретных грабель, греп, доли секунды | нет, советует |
| `blocked-hosts.mjs` | показ страницы не зависит от чужого сайта | да |
| `sync-design` | эталон не разошёлся с продуктом | нет, советует |

Сторож живёт в календаре (`glagol-calendar/scripts/ui-guard.mjs`) и зовётся
соседними проектами по относительному пути: один список правил на все
продукты, иначе разъедутся и продукты.

Ложное срабатывание глушится комментарием строкой выше, и только с причиной:
`{/* ui-guard-ignore: подпись не меняет высоту, проверено */}`. Без причины
глушить нельзя — правило перестанет что-либо значить.

## Адаптивные правила сторожа

Заведены в v3.0.0, потому что требование от 01.11.2026 прозвучало дважды, а
что прозвучало дважды — становится проверкой:

- **горизонтальная прокрутка на 375** — страница не шире окна;
- **область касания 44×44** у кнопок, пунктов меню и строк списка, с учётом
  предусмотренных системой исключений;
- **таблица без мобильного представления** — либо плитки, либо своя
  прокрутка;
- **нативные `date` и `select`** — запрещены;
- **`flex-1` с фиксированной высотой в колонке** — было и раньше, это
  образцовый пример того, как мобильный баг становится правилом.

## Контрольный экран

`lab/новый-экран.html` — доказательство, что по стандарту можно собрать
страницу, ничего не изобретая. Он помечен `data-ds="3"`, берёт настоящие
`tokens.css`, `work.css` и `ds3.css`, и в его собственном `<style>` нет ни
одного значения системы — только раскладка.

Что он должен показывать: плакат заголовка, заголовки разделов, подписи,
кнопки трёх видов, круглые кнопки, управление правкой, поля, плитки-строки,
чипы состояния и ссылку-кнопку. Если новый приём системы не попал на этот
экран, его негде проверить глазами, и он попадёт в продукт непроверенным.

## Снимки экранов

`glagol-atlas` — Playwright и pixelmatch. Каждый экран снимается в четырёх
видах: **телефон 375 и десктоп 1280 × светлая и тёмная.** Меньше нельзя:
половина расхождений живёт именно в тёмной теме и в мобильной раскладке, а
смотрим мы обычно светлую на большом мониторе.

```bash
cd ~/dev/glagol-atlas
npm run shot      # снять
npm run diff      # что изменилось против эталона
npm run accept    # принять новые снимки эталоном
```

До правки — `shot` и `accept`, после — `shot` и `diff`: он покажет и те
экраны, которых не трогали.

**`accept` не запускается не глядя.** Принятый вслепую снимок узаконивает
ошибку, и регрессионная проверка начинает защищать именно её. Смотрим diff
глазами, потом принимаем.

Экраны дизайн-системы и Design Lab входят в атлас своей секцией. Эталоны
концепций лежат отдельно от эталонов продукта: концепции меняются часто, и
смешивать их с продуктовой базой нельзя.

## Что смотрим глазами

Команда ловит грабли, а не качество. На 375 и 1280, в обеих темах:

- **композиция** — видно, что здесь главное, с первого взгляда;
- **иерархия** — кеглей не больше трёх, и каждый означает своё;
- **читаемость** — подписи не мельче 11, текст не сливается с фоном;
- **доступность действий** — главное действие видно без прокрутки;
- **плотность** — на компьютере нет пустых полей шириной в полэкрана, на
  телефоне ничего не прилипло к краю;
- **ничего не скачет** — замер `getBoundingClientRect()` до и после действия.

Проверка — `.claude/skills/glagol-visual-review/SKILL.md`: он ссылается на эти
документы и работает как независимый критик. Он не заменяет просмотр человеком:
последнее слово за Артёмом.

## Что проверяется на новом, а что на старом

Стандарт 01.11.2026 обязателен для новой работы и не требует переделки
работающего (`RULES.md`, «Постепенная миграция»). Проверки устроены так же:
**молчат на старом, строги на новом.**

Признак один и явный — файл несёт `data-ds="3"`. Списка путей не заводим: он
протухает за неделю, а атрибут живёт в самом файле и виден тому, кто этот
файл открыл.

| Правило сторожа | Где спрашивает |
| --- | --- |
| Нативный календарь и список системы | везде |
| Ширина шире телефона без оговорки | везде |
| Таблица без мобильного представления | везде |
| Экран без мобильной раскладки | везде |
| Форма без вопроса перед уходом | везде |
| **Кегль числом вне лестницы** | только `data-ds="3"` |
| **Самодельная кнопка** | только `data-ds="3"` |
| **Своё сжатие по нажатию** | только `data-ds="3"` |
| **Поле ввода мельче шестнадцатого** | только `data-ds="3"` |

Старые экраны поэтому могут держать исторические исключения сколько угодно
долго — сторож их не видит. Но как только раздел переработан и помечен,
нарушения в нём становятся ошибкой: «заодно поправим потом» — это и есть
способ не поправить никогда.

Проверено обоими концами 01.11.2026: на настоящем коде календаря четыре
новых правила молчат, на файле с четырьмя нарушениями и атрибутом дают четыре
находки.

## Три обхода, которые были закрыты 01.11.2026

Проверено до первого нового экрана, по вопросам Артёма. Все три — настоящие
дыры, не предположения.

**Новая страница без признака проходила всё.** Правила стандарта спрашивали с
файлов, помеченных `data-ds="3"`, — значит, достаточно было не поставить
атрибут. Закрыто правилом «новый экран без признака дизайн-системы»: сторож
спрашивает у git, что в ветке добавлено относительно `main`, и требует признак
с новых `page.tsx`, `layout.tsx` и `*-screen.tsx`. Новый **компонент** признака
не несёт — он попадает в область через импорт, и это правильно: компонент,
который зовут со старого экрана, стандарту не обязан.

**Компоненты рядом с экраном не проверялись.** Признак стоит на экране, а
кнопки живут в импортируемых файлах — достаточно было перенести самодельную
кнопку в соседний файл. Закрыто: область стандарта считается по импортам, всё
достижимое из помеченного файла тоже в области.

**Портал выпадал из области целиком.** Замер показал: кнопка 13/700 с
браузерной рамкой и без заливки, поле тринадцатым кеглем. Закрыто правилом
«портал без признака дизайн-системы» и записью в `docs/COMPONENTS.md`: корень
портала несёт `work` и `data-ds="3"`.

Проверено обоими концами: на настоящем коде календаря все правила молчат; на
пробных файлах — новый экран без признака, самодельная кнопка в импортируемом
компоненте и портал без признака — сторож даёт три находки и указывает строки.

Заодно поймана ошибка в самой проверке: git отдаёт кириллические имена
восьмеричными экранами, и правило молчало на всех русских путях. Лечится
`core.quotePath=false`.

## Витрина не имеет права врать о продукте

Оплачено дважды за один час 01.11.2026. Сначала страница сверки рисовала
`.work-btn` браузерную рамку `2px outset` — в продукте её сбрасывает preflight
Tailwind, а на статической странице сброса не было. По этой несуществующей
обводке Артём выбрал вариант главного действия. Через час то же повторилось с
синим кольцом наводки у поля.

Витрина, которая врёт о продукте, **принимает решение за человека**. Поэтому:

- сброс кнопки и кольцо наводки едут вместе со слоем `app/ds3.css`, а не
  живут правкой отдельной страницы;
- `lab/shoot.mjs` читает собственный `<style>` контрольного экрана и падает,
  если там появился вид, а не раскладка: цвет, кегль, вес, радиус, подложка.
  Раскладку писать приходится — Tailwind в статической странице нет, — а вот
  значения системы изобретать нельзя;
- `lab/build.mjs` собирает `tokens.css`, `work.css` и `ds3.css` из файлов
  `app/`, а не хранит копии.

## Критерий готовности

«Готово» — только про то, что воспроизвели: «нажал X → увидел Y». Не
проверяли — пишем «не проверяли». Функция, не открытая на телефоне, не принята.
