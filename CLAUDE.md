Общие правила работы — в `../CLAUDE.md`. Здесь то, что своё.

Версия системы — поле `version` в `package.json`. Другого номера нет.

## Что читать перед работой

Пять документов, точка входа — `README.md`:

- `RULES.md` — обязательное всем, источники истины, разрешение противоречий;
- `docs/DESIGN.md` — визуальный язык: одна система, две среды применения;
- `docs/COMPONENTS.md` — что уже есть, высоты, радиусы, кнопки, поля;
- `docs/ADAPTIVE.md` — телефон и компьютер, по два ответа у каждого паттерна;
- `docs/CHECKS.md` — чем проверяется и что считается приёмкой.

**`RULES_v1.31.md` и `RULES_v2.md` больше не правила.** Они лежат в
`docs/archive/` как происхождение приёмов. Значения оттуда брать нельзя:
высоты кнопок, краски рабочей среды и цветовая модель в них разошлись с кодом.
Что именно разошлось — `CHANGELOG.md`.

## Чем этот проект является

Сводом правил вида и витриной живых элементов продукта.

Чем он **не** является: местом, где рождается интерфейс. Компоненты в
`components/booking/` и `app/work.css` — копии из календаря, они попадают сюда
командой `npm run sync-design -- --write`, запущенной в календаре. Править их
здесь бессмысленно: при следующем переносе правка исчезнет.

Если эталон и продукт разошлись — прав продукт, а эталон отстал. 30 июля они
разошлись по трём файлам, и страница эталона четверо суток показывала кнопку с
обводкой, которой в проде нет.

## Команды

```bash
npm run dev      # локальный сервер, порт 3031
npm run check    # типы, вёрстка, сверка с продуктом
npm run lab      # снимки и проверки Design Lab
```
