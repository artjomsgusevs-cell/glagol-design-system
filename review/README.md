# Сверка интерфейса

Опубликованная страница разбора: что в работающих продуктах бюро делает одно и
то же, но выглядит по-разному, и что я предлагаю считать единым стандартом.

Адрес — в последнем сообщении сессии и в журнале телеграм-канала бюро.

Страница ничего не утверждает сама. Решения принимает Артём; принятое потом
переезжает в `docs/COMPONENTS.md` и `app/work.css`, а не остаётся здесь.

## Чем она отличается от Design Lab

`lab/` показывает систему такой, какая она есть, и три концепции «Глагола 2.0».
`review/` показывает **расхождения** — по одной карточке на роль элемента: что
нашлось в коде, сколько раз, где именно и что с этим делать.

## Файлы

| Файл | Что в нём |
| --- | --- |
| `index.html` | вся страница: шапка, разделы А–Д, подвал |
| `review.css` | обстановка страницы и образцы, собранные по классам Tailwind из кода |
| `review.js` | переключатели темы и ширины сцен |
| `shoot.mjs` | снимки 1440 и 375 в обеих темах и проверки |
| `shots/` | снимки и `ОТЧЁТ.txt` последнего прогона |

Токены и краски рабочей среды лежат в `lab/tokens.css` и `lab/work.css` — их
собирает `node lab/build.mjs` из `app/globals.css` и `app/work.css` продукта.
Второй копии здесь нет: сервер съёмки отдаёт их из соседней папки, а при
публикации они кладутся рядом со страницей теми же файлами.

## Как обновить

```bash
node lab/build.mjs      # вынуть свежие токены и work.css из продукта
node review/shoot.mjs   # снимки и проверки
```

Проверки смотрят: горизонтальную прокрутку на 375, область касания меньше 44
**вне сцен с образцами** (на сценах мелкие кнопки — предмет разбора, а не
ошибка), подхват шрифтов, применение темы и ошибки в консоли.

## Границы

- Продукт, токены, общие компоненты и правила этой папкой не трогаются.
- Версия системы не поднимается: сверка не меняет стандарт, она его готовит.
- Концепции A, B и C лежат в `lab/` отдельно; их элементы сюда не переносятся.
- Данные на образцах выдуманные.
